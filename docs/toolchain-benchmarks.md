# 外部ツールチェーンとの比較

`benchmarks/compare.mjs` は、同じ処理を実装したソースを複数のコンパイラでビルドし、
実行結果を検証したうえでサイズ・時間を記録するランナーです。
Node.js の標準ライブラリだけを使用し、製品に比較用の依存を追加しません。

## 実行

まず比較対象のコンパイラと必要なターゲットをインストールしてください。
ランナーはツールやライブラリを自動ダウンロードしません。

```sh
node benchmarks/compare.mjs benchmarks/compare.example.json
```

付属設定は fsw 単体の動作確認用です。Windows で Visual Studio ジェネレーターを使った場合は、
設定内の実行ファイルを `{root}/build/Release/fsw.exe` に変更します。
複数処理系の設定や計測結果をローカルに保存する場合は、Git 管理外の `artifacts/` を利用できます。

```sh
node benchmarks/compare.mjs artifacts/toolchain-comparison/local-config.json > artifacts/toolchain-comparison/results.json
```

設定は信頼できるものだけを実行してください。指定したコマンドを実行します。
シェルによる展開は行いません。

## 設定

`schema` は 1。`samples` は 3～1000（既定 15）、`warmups` は 1～100（既定 3）、
`runtime_samples` は 3～100（既定 7）です。
`timeout_ms` は各ビルドの上限で、既定は 180,000 ms です。

| フィールド | 意味 |
|---|---|
| `tools[].id` | 一意の識別子。英数字・`_`・`-` |
| `label` | 結果に表示するラベル |
| `extension` | `fixtures/` から選ぶソースの拡張子 |
| `version` | バージョンや固定リビジョンを確認するコマンド配列 |
| `build` | プロファイル名をキーとするビルドコマンド配列 |
| `path` | 子プロセスの PATH の先頭に追加するディレクトリ配列 |
| `env` | 子プロセスだけに設定する環境変数 |
| `startup` | インスタンス化後に一度呼び出す引数なし関数。不要なら省略 |
| `text_abi` | `utf8` または `utf16-object` |
| `components` | 追加ツールの名前とバージョン確認コマンド |
| `auxiliaries` | 生成される補助ファイル名の配列 |

コマンド・環境変数では `{root}`（リポジトリ）、`{source}`（入力）、
`{output}`（出力）、`{directory}`（そのケース専用ディレクトリ）、
`{cache}`（そのツール用キャッシュ置き場）が使用できます。
バージョン確認コマンドには、ケースごとの `{source}`・`{output}` は使用できません。

キャッシュの場所を強制変更することはありません。必要な環境変数を `env` に指定してください。
`{cache}` に設定したディレクトリは測定終了時に削除されます。
`workloads` を指定すると `add`、`kernels`、`micro-app` の一部だけを再測定できます。

## 処理内容と公平性

| 入力 | 処理 |
|---|---|
| `add` | 外部 ABI が i32 の加算 |
| `kernels` | 加算、再帰フィボナッチ、ビット演算を使う非線形チェックサム |
| `micro-app` | 初期化、再帰計算、Unicode テキストと数値を渡すホスト呼び出し |

各ソースは元のディレクトリから切り離して一つずつビルドします。
同じパッケージ内の別ファイルを自動読み込みする処理系でも、他のケースの宣言を混ぜません。
比較元の記事や既存アプリケーションと同じプログラムを再現するものではありません。
動的な文字列スライス、GC の負荷、非同期処理、実ブラウザーの DOM 描画は測定しません。

外部数値 ABI は i32 です。桁あふれと引数の整数化、関数の引数数、計算結果、
ホスト呼び出しの順序と Unicode テキストを検証します。
文字列の内部表現は統一していません。UTF-8 のデータポインター＋バイト長、
または UTF-16 オブジェクトポインター＋コード単位数を、共通の検証用ホストで読み取ります。
この表現差も生成サイズとホスト境界コストに含まれます。

`benchmarks/host.mjs` は DOM 呼び出しを模したテキスト・数値の記録器です。
そのサイズは全ケースに共通の補助コードとして別記します。
未知のインポート、不正な文字列境界、足りない初期化関数はエラーにします。

## 計測値

ビルドは毎回別プロセスで実行し、ウォームアップ後は利用可能なキャッシュを再利用します。
各ラウンドで実行順を回転させ、特定の処理系が常に最初・最後にならないようにします。
`first_observed_build_ms` は各ケースの初回観測値であり、コールドマシンやインストール時間ではありません。

ビルド時間はプロセス起動から終了までです。結果ファイルの検査・圧縮はその時間に含めません。
毎回生成物が一致することを確認し、失敗・不正な Wasm・誤答を測定結果として採用しません。
実行時間は 10 回ウォームアップ後に複数バッチを測り、1 呼び出し当たりの中央値と P90 を記録します。

Wasm は生サイズ、gzip level 9、Brotli quality 11、SHA-256 を記録します。
圧縮ヘッダーのため、ごく小さなファイルでは圧縮後のほうが大きくなる場合があります。
初期線形メモリ、実際のインポート・エクスポートも保存します。
コンパイラ実行ファイルのサイズは識別用であり、共有ライブラリや SDK を含むツールチェーン総量ではありません。

自動生成された補助ファイルと、実行に必要な補助ファイルは区別します。
このランナーはコンパイラ固有の JavaScript を読み込まずに全動作を検証できたケースだけを採用します。
したがって、記録した自動生成ファイルが必須の転送量とは限りません。

出力には全サンプル、ランナーと設定のハッシュ、コマンドのプロファイル、ツール・コンポーネントのバージョン、
ソースとバイナリのハッシュを含めます。設定と合わせて保存し、異なる ABI・機能・最適化条件の
数値を単一の順位にまとめないでください。
