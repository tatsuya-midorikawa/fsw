# ベンチマーク

このページは fsw 自身の測定結果です。特定の入力・環境での結果であり、
あらゆるソースや実行環境で最速・最小であることを示すものではありません。
生データと SHA-256 は [baseline.json](../benchmarks/baseline.json) に保存しています。

## 再実行

リリース構成でビルドし、ほかの重い処理と同時に実行しないでください。

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
cmake --build build --config Release --parallel 2
node benchmarks/bench.mjs
```

第 1 引数で実行ファイル、第 2 引数で測定回数を指定できます。

```sh
node benchmarks/bench.mjs build/fsw 21
```

Windows の例:

```powershell
node benchmarks/bench.mjs build/Release/fsw.exe 21
```

測定回数は 3～1000、既定は 21 です。JSON を標準出力に書き、
ソース・生成物は一時ディレクトリで扱って終了時に削除します。
コンパイル失敗、無効な Wasm、誤った実行結果を成功として記録しません。

## 計測方法

各入力について別プロセスで 3 回ウォームアップした後、21 回コンパイルしています。
キャッシュされた同一プロセス内でコンパイルを繰り返すベンチマークではありません。

| 指標 | 含むもの |
|---|---|
| CLI 全体 | Node.js からのプロセス起動、入力読み込み、コンパイル、一時ファイルからの置換、終了待機 |
| コンパイラ本体 | `--stats` の `compile_ms`。字句解析から Wasm 生成まで。入出力・プロセス起動は含めない |
| Wasm サイズ | 生成ファイルそのもの。圧縮前 |
| 初期メモリ | インスタンス化直後の Wasm 線形メモリ。ネイティブコンパイラの RSS ではない |
| 実行時間 | ウォームアップ後の Node.js WebAssembly。呼び出しオーバーヘッドを含む |

中央値と P90 はソート済みサンプルの `floor((n - 1) * q)` 番目で求めます。
`compile_ms` の分解能は 0.001 ms です。実行時間は 10 回ウォームアップし、
7 バッチの 1 呼び出し当たり時間の中央値を記録しています。

## 保存済みの測定

日時: **2026-09-13 17:14 UTC**。
環境: Apple M1 Max、macOS / Darwin 25.6.0、arm64、AppleClang 21.0.0、
CMake Release（`-O3 -DNDEBUG`）、Node.js 20.17.0。
コンパイラは `fsw 0.1.0-dev`、実行ファイルは **276,960 バイト（約 270.5 KiB）**。
追加の strip はしていません。製品のネイティブ依存は macOS の標準 C++ ライブラリとシステムライブラリです。

| 入力 | 入力 B | Wasm B | 初期メモリ B | 本体中央値 ms | CLI 中央値 ms | CLI P90 ms |
|---|---:|---:|---:|---:|---:|---:|
| 加算 1 関数 | 20 | 41 | 0 | 0.023 | 3.6474 | 4.7078 |
| `examples/math.fs` | 365 | 240 | 0 | 0.069 | 3.5679 | 4.5336 |
| 1,000 個の公開関数 | 20,780 | 17,729 | 0 | 2.019 | 6.3825 | 8.1777 |
| `examples/arrays.fs` | 471 | 680 | 65,536 | 0.093 | 4.1312 | 6.9928 |

最小例は `let Add a b = a + b` と末尾の改行です。
大量関数の入力は `let fN x = x + N` を `N = 0..999` で生成します。
すべて公開関数なので、未使用宣言の削除によって入力全体が消える測定ではありません。

| 実行内容 | バッチ当たりの呼び出し回数 | 1 呼び出し中央値 |
|---|---:|---:|
| 再帰版 `Fibonacci(28)` | 5 | 1,279,233.4 ns |
| 蓄積引数版 `FibonacciFast(40)` | 100,000 | 17.09 ns |
| `Sum(10000)` | 1,000 | 8.46 ns |

`FibonacciFast` はソース自体が線形時間のアルゴリズムです。
再帰版をコンパイラが動的計画法に書き換えているわけではありません。
`Sum` では整数和ループの式変換が働くため、一般的なループの速度を表す数値ではありません。
ナノ秒級の測定は呼び出し方法、JIT、タイマー、CPU の状態に強く影響されます。

## 限界

Windows / Linux の実測値、コールドキャッシュ時、コンパイラのピーク RSS、
大規模アプリケーション、長時間の逃避するオブジェクトの割り当て、
別の Wasm エンジンは、この保存結果に含みません。

機能の対応範囲や検査を減らした結果を、同じ機能を持つ処理の高速化とは扱いません。
コード・ビルド設定・エンジンを変更した場合は再測定してください。
