# fsw の言語仕様と Wasm ABI

対象は `0.1.0-dev`。F# の計算用サブセットであり、F# 全体や .NET の実装ではありません。
対応範囲の値・評価順序・演算を .NET 10 の F# と照合しています。
対応しない構文・型は診断を出し、別の意味のコードとして実行しない方針です。

## ソースと宣言

UTF-8、BOM、LF／CRLF、`//` コメント、入れ子の `(* ... *)` コメントに対応します。
インデントにはスペースを使います。識別子は ASCII または二重バッククォート形式です。
診断の列番号は 1 から始まる UTF-8 のバイト位置です。

```fsharp
module Sample

let offset = 2 * 3
let private hidden = 1
let mutable counter = 0

let add (left: int) (right: int) : int = left + right
let ``answer value`` () = 42
```

ファイル先頭の `module` は省略可能です。モジュールは一つで、名前のドット区切りと
同一モジュール内の修飾参照に対応します。複数ファイル、入れ子のモジュール、
`namespace`、パッケージ解決には対応していません。

トップレベルの値の初期化には、リテラル、先行する定数、折り畳み可能な演算式を使います。
動的な初期化、トップレベルの関数呼び出し、トップレベルの `do` は未対応です。

通常の参照先は先に宣言してください。自己再帰は `let rec`、相互再帰は
`let rec ... and ...` を使います。トップレベル宣言は別々の行の先頭から始めます。

```fsharp
let rec even n =
    if n = 0 then true
    else odd (n - 1)
and odd n =
    if n = 0 then false
    else even (n - 1)
```

## 型

| F# の型 | Wasm 上の表現 |
|---|---|
| `int` / `int32` | `i32` |
| `int64` | `i64` |
| `float` / `float64` / `double` | `f64` |
| `bool` | `i32` の 0 または 1 |
| `unit` | 引数・結果から省略 |
| `string` | UTF-16 オブジェクトへの `i32` ポインター |
| `int array` / `int[]` | `i32` 配列へのポインター |
| `int64 array` / `int64[]` | `i64` 配列へのポインター |
| `float array` / `float[]` | `f64` 配列へのポインター |
| `bool array` / `bool[]` | 要素が 4 バイトの真偽値配列へのポインター |

関数の型推論は**単相**です。同じ関数を異なる型に特殊化しません。
算術の未確定型は `int`、未確定の配列要素型は `int` に既定化します。
それでも曖昧な型には注釈が必要です。

```fsharp
let add a b = a + b
let identity (x: float) = x
let first values = values.[0]
```

`let identity x = x` 単独では型が確定しません。汎用のジェネリック関数としては公開できません。
数値型の暗黙変換も行いません。`int64` のリテラルには `1L` のように `L` を付けます。

## 式と制御構造

関数はカリー化された宣言・呼び出し構文に対応しますが、呼び出しではすべての引数を渡します。
関数値、部分適用、ラムダ、クロージャー、ローカル関数は未対応です。

```fsharp
let twice x = x * 2

let calculate input =
    let adjusted = input + 1
    adjusted |> twice
```

`let ... in ...`、ローカル変数のシャドーイング、式列、`ignore`、`do`、
`if / then / elif / else`、`while / do`、整数の `for` に対応します。
通常の式列の途中の式は `unit` にしてください。明示的な `do` はその式を評価して結果を捨てます。
複数行の式は `=`、`then`、`else`、`do` の次の行をインデントする形を使ってください。
F# のすべての行継続・オフサイド規則を扱うわけではありません。

```fsharp
let sum (limit: int) =
    let mutable total = 0
    for i = 1 to limit do
        total <- total + i
    total

let countdown start =
    let mutable remaining = start
    while remaining > 0 do
        remaining <- remaining - 1
```

`for i = low to high`、`for i = high downto low`、`for i in low .. high` に対応します。
上下限は左から順に一度だけ評価します。終端は含まれ、空の範囲は実行しません。
終端が `Int32.MinValue` / `Int32.MaxValue` に相当する場合も、カウンターの桁あふれで
ループを継続させません。ステップ付きの範囲は未対応です。

`match` は数値・真偽値・文字列リテラル、変数、`_`、リテラルの OR パターン、
`when` ガードに対応します。網羅性を要求し、到達不能な後続アームはエラーにします。

```fsharp
let classify value =
    match value with
    | 0 -> 10
    | 1 | 2 -> 20
    | x when x < 0 -> 30
    | _ -> 40
```

対応演算子は `+ - * / % = <> < > <= >= && || &&& ||| ^^^ <<< >>> ~~~ |> <| <-` と単項 `+ -`。
対応範囲の優先順位は F# に合わせています。`&&`、`||` は短絡評価します。
`|>` は左辺を先に評価してから、右辺の関数引数を評価します。

## 数値の意味

整数の加算・減算・乗算・符号反転は型の幅で折り返します。シフト数は
`int` で、32 / 64 ビットの幅に応じてマスクします。整数の右シフトは算術シフトです。

整数のゼロ除算、最小値の `-1` による除算・剰余、最小値の `abs` はトラップします。
Wasm の剰余命令だけではこのオーバーフローを再現できないため、明示的に検査します。
トラップはホストから `WebAssembly.RuntimeError` として見えます。
.NET の例外オブジェクトや `try / with` を提供するものではありません。

浮動小数点は `f64` です。整数のような再結合や高速近似は行いません。
NaN、無限大、負のゼロは浮動小数点値として扱います。NaN のペイロードは保証しません。
浮動小数点の `%` は未対応です。

| 組み込み | 対応 |
|---|---|
| `not` | 真偽値 |
| `abs` | `int`、`int64`、`float` |
| `min` / `max` | 同じ整数型の 2 引数 |
| `sqrt` / `floor` / `ceil` / `truncate` | `float` |
| `int` / `int32` / `int64` / `float` / `float64` / `double` | 数値型間の明示変換 |
| `ignore` | 値を評価し、結果を捨てる |

`int64` から `int` への変換は下位 32 ビットを使用します。浮動小数点から整数への変換は
.NET 10 の動作に合わせ、ゼロ方向への丸め、範囲外の飽和、NaN から 0 への変換を行います。

## 配列と文字列

```fsharp
let make count = Array.zeroCreate<float> count
let filled count = Array.create count 42
let literal () = [| 1; 2; 3 |]
let empty () = ([||] : int array)
let length (values: int array) = values.Length
let get (values: int array) index = values.[index]
let set (values: int array) index value = values.[index] <- value
```

`Array.length` も使えます。負の長さ、負の添字、範囲外アクセス、メモリ上限超過はトラップします。
配列の要素代入は、配列・添字・右辺を順に評価してから境界を検査します。
配列の等価比較、スライス、多次元配列、参照型の配列は未対応です。

文字列は通常のリテラル、単一行の `@"..."` 形式、エスケープ、
連結 `+`、UTF-16 コード単位による順序比較、等価比較、`.Length`、`String.length` に対応します。
補助平面の文字は 2 コード単位です。文字列の添字、補間、三重引用符、複数行リテラルは未対応です。
エスケープは `\\`、`\"`、`\'`、`\n`、`\r`、`\t`、`\b`、`\a`、`\f`、`\v`、
`\uNNNN`、`\UNNNNNNNN`、3 桁の十進数（0～255）に対応します。

## ホスト関数

`DllImport` の構文で Wasm インポートを宣言します。OS の DLL をロードする機能ではありません。
属性のモジュール名・`EntryPoint` は Wasm のインポート名です。

```fsharp
open System.Runtime.InteropServices

[<DllImport("host", EntryPoint="log")>]
extern void log(int value)

[<DllImport("host")>]
extern int combine(int left, int right)

let run () =
    log 42
    combine(20, 22)
```

複数引数の `extern` 呼び出しにはタプル形式を使います。引数なしは `extern int read()` と
`read ()` です。`void` は `extern` の戻り値でのみ使えます。
インポート名には通常の引用符または単一行の逐語的文字列を使用できます。
通常の文字列中のバックスラッシュエスケープ、`EntryPoint` 以外の属性引数は未対応です。

`open` は `System` と `System.Runtime.InteropServices` のみ認識します。
.NET ライブラリの読み込みや名前空間の一般的な探索は行いません。

## 公開 ABI

公開 `let` 関数は名前を変えずに Wasm 関数としてエクスポートします。
トップレベルの公開値は Wasm グローバルとして公開し、JavaScript では `.value` で参照します。
`private`、インポート、`_` は既定では公開しません。
`--export NAME` を指定すると、明示した宣言のみを公開します。

JavaScript では `i64` に `BigInt`、`i32` と `f64` に `Number` を渡します。
真偽値は数値として受け渡し、入口で非ゼロ値を 1 に正規化します。
`unit` の関数戻り値は `undefined`、トップレベルの `unit` グローバルは 0 です。

メモリを使うモジュールだけが `memory` をエクスポートします。その場合、同名の公開宣言は
エラーになります。文字列と配列は 8 バイト境界のポインターで、0 は無効です。

| オフセット | 内容 |
|---|---|
| `pointer + 0` | `u32` の要素数。文字列では UTF-16 コード単位数 |
| `pointer + 4` | `u32` の型タグ |
| `pointer + 8` | リトルエンディアンの要素データ |

型タグは `string = 5`、`bool array = 6`、`int array = 7`、
`int64 array = 8`、`float array = 9` です。
文字列の要素幅は 2 バイト、真偽値・`int` は 4 バイト、`int64`・`float` は 8 バイトです。

ホストは配列の要素データだけを変更してください。ヘッダー・文字列を書き換えたり、
ポインターを別のインスタンスに渡したりしないでください。
コンパイラは参照の範囲・アラインメント・型タグと配列境界を検査します。
これは同じメモリを共有する悪意あるホストを隔離する仕組みではありません。

メモリの拡張で既存の `ArrayBuffer` ビューが無効になることがあるため、
ホストは各操作で `exports.memory.buffer` からビューを取り直してください。
UTF-16 の孤立サロゲートまで保存する必要がある場合は `DataView.getUint16(..., true)` と
`String.fromCharCode` を使います。`TextDecoder` は不正な UTF-16 を置換します。

## メモリ寿命と最適化

数値だけのモジュールは線形メモリも補助ランタイムも持ちません。
メモリが必要なら最小ページ数で開始し、64 KiB 単位で拡張します。
既定の上限は 256 ページ（16 MiB）。`--max-memory-pages` で変更できます。

汎用 GC はありません。割り当てはバンプ方式です。
最適化が有効な場合、自己再帰以外のユーザー関数・ホスト関数を呼ばず、グローバルに書き込まず、
参照を返さない関数では、正常終了時にその関数の一時割り当てをまとめて解放します。
参照引数を持たない自己末尾再帰では、次の反復に入る前にも解放します。
外へ返す参照やホストに渡す参照はこの回収の対象外です。

トラップ時の巻き戻し、一般的な到達可能性解析、逃避するオブジェクトの GC はありません。
トラップ後にメモリ状態の復旧が必要な場合や、長時間割り当て続ける処理では、
新しいインスタンスを作り直してください。

最適化は定数畳み込み、定数分岐の除去、未使用宣言の除去、自己末尾呼び出しのループ化、
整数加算を伴う再帰のアキュムレーター化、単純な整数和ループの式変換を行います。
整数和の変換は 64 ビット中間値で桁あふれ・負の範囲・空範囲を扱い、浮動小数点には適用しません。
相互再帰のスタック消費は削減しません。

`--no-opt` は定数畳み込み・整数和ループの式変換・末尾再帰最適化・領域回収を無効にします。
未使用宣言の除去と、安全性に必要な検査は無効にしません。

## 制限

ソースは 16 MiB、トークンは 2 Mi 個、構文・式の深さは内部カウントで 256、
関数の引数は 256 個、定数文字列の総格納量は 64 MiB に制限しています。
メモリ上限に指定できる値は 1～32767 ページです。

レコード、判別共用体、クラス、インターフェース、ジェネリクス、高階関数、リスト、
シーケンス、計算式、例外構文、非同期、WASI、スレッド、SIMD、.NET 相互運用は未対応です。
一般的なタプルも未対応で、現在は `extern` の引数にだけ使用できます。

生成するバイナリは Wasm version 1 の形式です。使う機能に応じて bulk memory と
飽和的な浮動小数点→整数変換の命令を含みます。
